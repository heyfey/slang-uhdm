## 2. THE THREE BREAKS — pristine-right, patched-wrong, on legal SV

Every arm below is its own `dut.sv`, golden regenerated by the pinned Surelog
v1.87, `golden_rc=0 ours_rc=0`, read through the implementer's own resolving
lister (`calist75.py`) and scored with their own `score75.py`.

### 2a. `xc_impw` — LAW B's WIDTH half SUPPRESSES a climb it should not

`genCaSubstAdjustW71` is `bindVariable`'s size walk and it CLIMBS into the
instantiating scope on a miss. The new import lookup returned whatever
`pkg->find(name)` answered — a PARAMETER, a TYPEDEF, a FUNCTION — and the
caller then `return`ed `caLhsAdjustBindSymW71(that)`, which is 0 for a
non-signal. The walk therefore stopped at a scope that has no holder and never
reached the outer signal it used to resize to.

A child module with `import pk::*` (`pk` holds `localparam int zz`,
`typedef logic [3:0] tt`, `function ff`) instantiated under a parent holding
8-, 12- and 4-bit signals of those names:

| row | golden | pristine | patched | verified |
|---|---|---|---|---|
| `tt` | `vpiSize:12` | **12** | **32 WRONG** | 12 |
| `ff` | `vpiSize:4` | **4** | **32 WRONG** | 4 |
| `nn` (no home anywhere) | 32 | 32 | 32 | 32 |

Attributed with the pass's own switch: `R11U75_IMPW_OFF=1` restores 12 and 4.

**FENCE:** `nsImportHome75` returns a Net or a Variable and nothing else.
`importPackage` copies the imported package's SIGNAL vector; a package
parameter/typedef/function puts nothing in the importing module's registry, so
`bindVariable` does not stop there. The BINDING half already filtered on the
same two kinds downstream, so it is unchanged by construction.

### 2b. `xf_crossblk` / `xh_ancpath` — LAW C folds a WRITTEN PATH golden leaves alone

LAW C's gate is "the base's declaring scope is a `GenerateBlock`".
`asmRefFamilyBase` accepts a `HierarchicalValue` as readily as a `NamedValue`,
so a base reached by a written path took the new road. Golden folds a SIMPLE
NAME and leaves a path symbolic — and on the symbolic cell it BINDS the cell's
own local, which § caGenScopeFoldedLhsNoOwnBind75 then stripped.

`xf_crossblk`, golden vs the patched binary (3 cells, both fields wrong):

| row | golden | pristine | patched | verified |
|---|---|---|---|---|
| `A1.a_own` (own block, simple) | folded, no actual | `hier_path` + actual | folded, no actual | golden's |
| `A2.a_cross` = `A1.A_LOC.n` (SIBLING block) | `hier_path` + `logic_var` | **golden's** | folded + **actual STRIPPED** | golden's |
| `A2.a_ct` (same, other member) | `hier_path` + `logic_var` | **golden's** | folded + stripped | golden's |
| `A3[i].a_it` (own block, per iteration) | folded 400/401 | `hier_path` | folded 400/401 | golden's |
| `A4.a_idx` = `A3[1].L_LOC.n` (another ITERATION) | `hier_path` + `logic_var` | **golden's** | folded + stripped | golden's |

`xh_ancpath` separates the two candidate rules and answers REFERENCE FORM, not
scope relation:

| row | golden |
|---|---|
| `B_LOC.n` — an ENCLOSING block's base by SIMPLE NAME | folded, no actual |
| `B1.B_LOC.n` — the SAME base by a written PATH | `hier_path` + own-local actual |
| `M_LOC.n` — a MODULE base by simple name | folded, no actual |
| `dut.M_LOC.n` — the SAME module base by a PATH | `hier_path` + own-local actual |
| `C_LOC.n` — this block's own base | folded, no actual |

On the implementer's own scorer both arms move AWAY from golden:
`xf_crossblk` gold_only 431 (pristine) -> **460** (patched) -> 399 (verified);
`xh_ancpath` 453 -> **467** -> 446.

**FENCE:** the record is gated on the member-select's base being a
`NamedValue`. On the gen-scope road that means no record at all (the cell is
golden-symbolic); on the pre-existing `caMemSel` road the push stays exactly as
pristine takes it and only `foldRec75` is withheld, so LAW D no longer strips
the actual golden carries on `dut.M_LOC.n`. The hierarchical MODULE base's
over-FOLD (`b_modp`'s Rhs) is PRE-EXISTING on the pristine binary and is left
alone — it is a residue, not this pass's ground.

### 2c. `xi_genimp2` — LAW B binds an actual golden does not have

`nsImportHome75` was asked of whatever scope the one-hop walk was searching,
including a GENERATE BLOCK. `importPackage` materialises the imported signals
in the COMPONENT's registries; a generate block that writes its own
`import pg::*` gets no holder, and golden binds nothing there.

| arm / row | golden | pristine | patched | verified |
|---|---|---|---|---|
| `xg_genimp` `G1[0].G2.g_ns` — gen-block import, module does NOT import | none | none | none | none |
| `xi_genimp2` `G1[0].k_ns` — target one hop from the MODULE body | `logic_var (work@dut.k_ns)` | none | golden's | golden's |
| `xi_genimp2` `G1[0].G2.g_ns` — one hop from a gen block that imports, module holder EXISTS | **none** | none | **`logic_var (work@dut.g_ns)` INVENTED** | none |

`xi_genimp2` ours_only 1 (pristine) -> **3** (patched) -> 1 (verified). This is
the pass-73 verifier's own break class: a cell wearing an actual golden does
not have.

**FENCE:** the import lookup in `genCaLhsNamesake74` is asked of an
`InstanceBody` only. The width walk already asked it inside its
`InstanceBody && DefinitionKind::Module` arm and is untouched.

  PACKED-array net namesake and an unpacked-array VARIABLE namesake both bind,

* `xa_bail` — LAW D does NOT over-fire on the four faces where our drain

  golden on every one; `R11U75_CASUPP_OFF=1` returns the arm to pristine
  exactly.
* `xd_glp2` — LAW C is right for a module instantiated TWICE and inside an
  INTERFACE's generate scope; every folded cell matches golden, and the
  symbol-keyed `genScopeParamObj75` does not leak one instance's object into

1. **The imported-package NET still has no holder of ours** — the implementer's
   own residue 1, unmoved (`g2_importshapes` `w_net`).
2. **A STRUCT package variable's holder is our `logic_var` where golden's is a
   `struct_net`** (`xe_impkind` `t_ns`). Head-for-head with pristine's
   `<null>`: the binding is right and the object's KIND is not, so the cell

   declines, where golden binds its `array_var` (`xe_impkind` `a_ns`). Both are
   the same hoist residue as 1, one level deeper.
3. **A HIERARCHICAL module-level base still over-FOLDS on the pre-existing
   `caMemSel` road** (`xh_ancpath` `b_modp`: golden `hier_path`, ours a folded
   constant). PRE-EXISTING on the pristine binary — the verified patch stops
   LAW D from also stripping that cell's actual, and leaves the fold alone
   because narrowing it is a different law with its own grid.
4. The pass's own residues 2-6 (the gen-scope parameter's `UINT` encoding, the
   `func_call` leftover argument, r11u69's R1 `g_sh`, the interface def-view
   gen-scope statements, `v4_lhsshape`'s concat actuals) stand unmoved and
   byte-identical on all three binaries.
