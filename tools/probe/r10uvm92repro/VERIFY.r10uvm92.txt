THE REFUTATION — prettyPrint's `var_select` ROW WAS TRANSCRIBED AND NOT WRITTEN
=============================================================================
`UHDM::ExprEval::prettyPrint` (ExprEval.cpp:1237) has a `var_select` row:

    case uhdmvar_select:
      out << vs->VpiName();
      for (e : vs->Exprs()) { out << "["; prettyPrint(e); out << "]"; }

It is the ONLY object kind in the whole dispatch that RE-EMITS BRACKETS.  It
appears in the shipped pass's header table AND in its README table, and it was
NOT in `ppIdxText92`.  Every multi-dimensional select operand therefore fell to
`default: return true` and rendered EMPTY -- or, when the OUTER level was a
range, as the bare `l:r` of a part_select Surelog never built.

THE BOUNDARY, measured on GOLDEN (arm `v92_b2_varsel.sv`), select chain over a
PLAIN IDENTIFIER:
    ONE level, ElementSelect   `one_d[2]`, `pv[5]`        bit_select    -> ""
    ONE level, RangeSelect     `pv[7:4]`                  part_select   -> `7:4`
    TWO OR MORE levels         `two_d[1][2]`  `uv[1][7:4]`  `pk3[1][2][3]`
                                                          VAR_SELECT    -> the
                                                                           WHOLE
                                                                           TEXT
Packed and unpacked behave the SAME.  Over a MEMBER ACCESS base it is a
hier_path at EVERY depth and renders EMPTY, at one level and at three.
Each `Exprs()` entry is itself prettyPrinted, so an inner range keeps its `l:r`
and an inner operand with no row renders EMPTY INSIDE ITS OWN BRACKETS
(golden `two_d[1][]` for `two_d[1][bb.q]`).

  golden  bb.bin[-two_d[1][2]]             shipped  bb.bin[-]

FIXED by the verifier in `ppIdxText92`: the ElementSelect and RangeSelect arms
are merged, the chain depth picks the object kind, and the var_select row is

WHY THE ORACLE DID NOT CATCH IT: `ct92cen` LINKS the real
`ExprEval::prettyPrint`.  Its EXPM_Y proof validates the transcription of
`decompileHelper` against golden -- it never compares the PRODUCTION C++
transcription of prettyPrint to the real one.  The gap between the oracle and
the emitter is exactly where this defect lived.
