## 2. THE DECODE (question 2)

### 2a. LAW A — an arm that is not there

`CompileHelper::compileNetDeclaration`
(`~/git-repos/Surelog/src/DesignCompile/CompileHelper.cpp:2131-2141`) walks
the declaration's siblings itself:

```cpp
nettype = fC->Type(NetType);
NodeId net = fC->Sibling(NetTypeOrTrireg_Net);
if (fC->Type(net) == VObjectType::paPacked_dimension) {
  List_of_net_decl_assignments = fC->Sibling(net);
} else {
  List_of_net_decl_assignments = net;
}
```

There is **no `paDrive_strength` arm and no `paCharge_strength` arm anywhere
in the function**.  When the declaration is written
`wire (strong1, weak0) [31:0] w = 32'd12;` that sibling IS the
`Drive_strength` node, so `List_of_net_decl_assignments` is bound to it; the
`paDelay3` / `paDelay_control` test immediately below (`:2144-2149`) fails,
`fC->Child(Drive_strength)` is the strength keyword rather than a
`Net_decl_assignment`, and the `while (net_decl_assignment)` loop
(`:2153-2210`) pushes NO `Signal` onto `component->getSignals()`.

Nothing downstream can put it back.  Every net `UhdmWriter` writes comes from
that vector, and `NetlistElaboration::elabSignal` — the signal walk that mints
the net-declaration-assignment cells (§ `caIfaceElabNetDeclAssignListing88`,
pass 87) — walks the same one.  The declaration vanishes from both views of
every home, net AND cell.

**THE PRODUCER SAYS IT IN ITS OWN VOICE.**  Arm `u11_strmodport` names the
dropped net in a modport and the pinned Surelog stops with

```
[ERR:CP0311] .../u11_strmodport/dut.sv:5:36: Undefined net used in modport: "w_str".
```

— the compiler reporting that its own net table has no such entry
(`golden_rc=4`; the arm is a DECODE witness, not a golden database, and is
recorded as such).

### 2b. LAW B — compiled as an expression, bound as a parameter

`CompileHelper::compileContinuousAssignment`
(`~/git-repos/Surelog/src/DesignCompile/CompileHelper.cpp:2440-2444`) hands
the `Delay3` node straight to `compileExpression` with `Reduce::No`:

```cpp
} else if (fC->Type(List_of_net_assignments) == VObjectType::paDelay3) {
  delay_expr = (expr*)compileExpression(component, fC, List_of_net_assignments,
```

name — and is never folded to a number.  `UhdmWriter::writeCont_assign`

```cpp
if (delay && delay->UhdmType() == uhdmref_obj) {
```

The bind is what separates the two views, and the **CLONE is why setting it in

`ca->Delay(dly83)`), so this pass clones the reference there for the same

## 4. THE TWO LAWS, GATED (question 4)

### LAW A — § `caNetDeclStrengthDropped90`

`netDeclStrength90(sym)` walks the symbol's syntax up to its
`NetDeclarationSyntax` and answers `strength != nullptr` (slang's
`NetStrengthSyntax` covers the drive AND the charge form, which is why
`u14_strcharge` is the same law).  An IMPLICIT net has no declaration and
answers no.  Two faces:

* `strNetDropped90(sym, isPortNet, site)` — the NET face, at all FIVE listing
  sites in `ModuleEmit.cpp`: `emitModuleDef` (`moddef`), `emitInstance`
  (`modelab`, which is also the program home), `emitInterfaceDef` (`ifdef`),
  `emitInterfaceInstance` (`ifelab`, home view and port views alike) and
  `emitGenScopes` (`gen`).  `isPortNet` is `u12_strnonansi`'s guard.
* `strCellDropped90(sym, site)` — the CELL face, stated INDEPENDENTLY, at
  `emitContAssigns`'s net-decl-assign loop (`modcell`) and at the gen scope's
  (`gencell`).  The interface home's cell was already declined by pass 87's
  `ifaceNdaCellMinted88`.

In a GENERATE scope the cell is built out of the net inside one block, so
there the net gate subsumes the cell gate; the `SWITCHES` ledger shows this
honestly (`u3`/`u4`: `STRCELL_OFF` equals `NONE`) and everywhere else the two
are independent (`u12`: `STRCELL_OFF=0`, `STRNET_OFF=52`; `q11`:
`STRCELL_OFF=120`, `STRNET_OFF=52`).

### LAW B — § `caDelayParamRefSpelling90`

`delayParamSym90(dsyn, scope)` answers only for a `DelayControl`, or a
`Delay3` with **no** closing paren, whose value is an `IdentifierName` that
names a `Parameter` in the holder's OWN body — walked by name over
`scope->members()`, with no lookup that could mint or specialize anything.
`emitAssignDelay` then builds the `ref_obj` at the `#`-through-name span with
`VpiName` and `VpiFullName`; `bindDelayParamRef90` sets `Actual_group` from
the instance's own `Parameters()` in the ELABORATED view only, and the
interface elaborated fold CLONES the reference before binding it.

GOLDEN WRITES NOTHING ON A MISS: when the instance carries no such parameter
the reference stays unbound, exactly as golden's definition view leaves it.
