1.  THERE ARE ONLY TWO ROADS TO ANY `vpiActual`, AND ONLY ONE OF THEM CAN
    ANSWER WITH AN ENUM CONSTANT
=============================================================================

ROAD 1 — the COMPILE-TIME eager bind.

    src/DesignCompile/CompileStmt.cpp:3089

          case uhdmbegin:     ... lscope->Variables()

    IT WALKS `Variables()` AND `Io_decls()` AND NOTHING ELSE.  There is no
    `Enum_consts()` arm, no `Param_assigns()` arm and no `getValue()` call in
    it.  ROAD 1 CAN NEVER RETURN AN ENUM CONSTANT — in ANY holder, in any
    window.  This is why § uninstIfaceBodyBindsInMethodWindow218's arm a2
    found the enum cells over-bound INSIDE and OUTSIDE its window alike (that
    pass's R4): the window is a ROAD 1 question and the enum constant is not
    on Road 1 at all.

    `writeInterface` OCCUPIES 1626-1794 AND NOT ONE OF THE CALLS ABOVE IS
    INSIDE IT.  (1623 is writeModule's tail, three lines before writeInterface
    begins.)  `writeInterface` is the ONLY writer for an interface DEFINITION,
    and its output is `uhdmallInterfaces` — the only listing an interface no
    instance elaborates ever appears in.  Such an interface has no netlist, so
    the elaborated-instance call at :4785 (`if (mod && netlist)`) never runs
    for it either.

    THEREFORE: for an interface DEFINITION THAT NO INSTANCE ELABORATES, ROAD 2
    NEVER RUNS AT ALL, and Road 1 cannot answer with a constant.  EVERY
    enum-constant reference in such a body is golden-BARE, unconditionally.

=============================================================================
4.  WHY THIS LAW CARRIES NO FENCE
=============================================================================

    § 218 needed a symbol test and a position test because Road 1 SURVIVES for
    an uninstantiated interface and Road 1 has structure.  § 220 needed two
    fences because `compileDatastructureTypespec` answers a PARAMETER and a
    visible TYPE NAME at COMPILE time, before the placeholder tail.

    Neither applies here.  The enum-constant actual has ONE producer, that
    producer is `lateBinding`, and `lateBinding` does not run.  There is no
    compile-time arm to carve out.  The grid measures the prediction directly:
    over 22 reference contexts x 5 enum homes x both golden views, an
    UNINSTANTIATED interface's body binds ZERO enum constants, while the SAME
    BODY in an INSTANTIATED interface binds 21 of 22 and in a MODULE 21 of 21.
    So the term is a bare `!uninstIfaceSubBody218` with nothing beside it.

    ONE CELL DESERVES ITS NAME: a `::`-QUALIFIED enum reference
    (`p221::PE_B`).  Golden FOLDS it to a `constant` and emits NO REFERENCE AT
    ALL — in the uninstantiated interface (a1 53:13) and in the instantiated
    one (a1 105:13) alike.  We emit a `ref_obj` there on both binaries.  That
    is a FOLD residue of a different family, pre-existing and unchanged by this
    pass; declining its actual moves the census cell from EXTRA-OURS to OTHER
    without making it agree or disagree any more than it already did, because
    golden has no reference for it to agree with.  It is recorded as R2.
