## 0. AN INSTRUMENT FIX — THE PER-CELL ARBITER'S KEY WAS BLIND TO A SHARED Lhs

`cacell88.py` inherits r11u85's `cont_assign` arbiter, and its `cellkey` read
the Lhs name off the dump's print of the Lhs object.  A SHARED Lhs — which is
exactly the net-decl-assign form where the cell's Lhs IS the listing net —
prints ABBREVIATED, a bare header with no `vpiName` **and no location at all**,
so the key fell back to the parenthesised FULLNAME and one cell scored
GOLD-ONLY on golden's side and OURS-ONLY on ours.  On `q7_ndamod`, an arm whose
`uhdm-cmp` verdict is `rc = 0`, the old key read **GOLD-ONLY 2 / OURS-ONLY 2**;
the fixed key reads **MATCH 11 / DIFF 0 / GOLD-ONLY 0 / OURS-ONLY 0**, which is
the judge's own answer.

The fix resolves the abbreviation through the same index `exprsig` uses, plus a
SECOND index on `(kind, parenthesised name)` for the abbreviations that carry no
span.  The FIELD comparison is unchanged, so an object that still cannot be
resolved stays **UNSCORED and printed**, never MATCH — r11v83's blind spot
stays closed (`n4_nestgen`'s `~constant@…` cell is still UNSCORED, a constant
having no name for the second index to key on).

## 2. THE DECODE (question 2)

### 2a. LAW A — the cells are the SIGNAL WALK's, not `writeCont_assign`'s

`NetlistElaboration::elabSignal`
(`~/git-repos/Surelog/src/DesignCompile/NetlistElaboration.cpp:2704-2723`)
ends its NET branch with:

```cpp
if (exp && ((!signalIsPort) || …)) {
  cont_assign* assign = s.MakeCont_assign();
  assign->VpiNetDeclAssign(true);
  fC->populateCoreMembers(id, id, assign);   // the declarator NAME's span
  assign->Lhs((expr*)obj);                   // the net object itself
  assign->Rhs(exp);
  if (sig->getDelay()) { … assign->Delay(delay_expr); }
  netlist->cont_assigns()->push_back(assign);
}
```

and `elab_interface_` (`:1846-1848`) runs `elab_ports_nets_` over the
INTERFACE instance's netlist with the same two passes a module gets — its
component-type switch names `paInterface_declaration` beside
`paModule_declaration` (`:2807`).  `UhdmWriter::writeElabInterface`
(`src/DesignCompile/UhdmWriter.cpp:4296-4303`) then hands that vector to
`UhdmWriter::writeCont_assign` (`:2090`), the identical call
`writeElabModule` makes at `:4146`, which reduces the Rhs, CLONES the cell and
`adjustSize`s the constant against the Lhs net's own typespec.

Three consequences, each measured below: the cells exist ONLY in the
elaborated view; their span is the NAME's; and the `else { // Vars }` branch
that follows hands a VARIABLE's initializer to `makeVar_` instead — so a
variable initializer mints no cell at all.

### 2b. LAW B — one `else if` in the producer's parser walk

`CompileHelper::compileContinuousAssignment`
(`~/git-repos/Surelog/src/DesignCompile/CompileHelper.cpp:2440-2455`) is handed
the FIRST child of the `Continuous_assign` node:

```cpp
if (fC->Type(List_of_net_assignments) == VObjectType::paDrive_strength) {
  … Strength0 / Strength1 …
  List_of_net_assignments = fC->Sibling(List_of_net_assignments);
} else if (fC->Type(List_of_net_assignments) == VObjectType::paDelay3) {
  delay_expr = compileExpression(…);
  List_of_net_assignments = fC->Sibling(List_of_net_assignments);
}
NodeId Net_assignment = fC->Child(List_of_net_assignments);
while (Net_assignment) { … }
```

The LRM orders them `assign [drive_strength] [delay3] list_of_net_assignments`,
so when BOTH are written the `if` arm takes the strength and the ONE advance
lands on the `Delay3` node.  `fC->Child(Delay3)` is the delay VALUE, whose
children are not a `Net_assignment` shape, so the loop binds no lvalue and the
function returns an EMPTY vector.  Nothing downstream can put the cell back:
`writeCont_assign` only ever transforms cells already in the netlist's vector,
and `NetlistElaboration::elaborate_` only pushes the definition's
`getContAssigns()` — which never received one.  Hence: **no cell in the
definition view, none in any elaborated view, and none in a gen scope**, and
the WHOLE comma list goes with it because the loop never starts.

### 2c. LAW C — the substituted value, and whose width it takes

`elabSignal` compiles the declaration's initializer in the INSTANCE's context
(`compileExpression(…, instance)`), so a NAME read comes back already reduced
to that instance's value; `writeCont_assign` (`:2246-2277`) reduces once more
and calls `CompileHelper::adjustSize(tps, …)` with `tps` from the Lhs NET's
typespec.  The observable, read off `q12_ndaparamenc` (sixteen cells, one
written form each), is TWO rules:

* the VALUE, the DECOMPILE and the CONSTTYPE are the parameter's own spelling,
  **verbatim, never re-encoded**;
* the WIDTH is the NET's — but only on the SUBSTITUTED copy.  A written
  LITERAL keeps its own.

### 2d. The producer's own DECLINE beside LAW A, decoded and NOT copied

`CompileHelper::compileNetDeclaration`
(`~/git-repos/Surelog/src/DesignCompile/CompileHelper.cpp:2131-2141`) reads the
sibling after the net keyword as either a `paPacked_dimension` or the
declaration list and has **no arm for `paDrive_strength` at all**, so

## 4. THE THREE LAWS, GATED (question 4)

### § caIfaceElabNetDeclAssignListing88 (`R11U88_NDA_OFF=1`)

> The ELABORATED interface lists a `cont_assign` per net-declaration
> assignment, `vpiNetDeclAssign:1`, spanning the declarator NAME, carrying the
> declaration's own delay, and preceding every written `assign`.  A VARIABLE
> initializer gets none, a reference-style PORT view gets none, and a
> declaration carrying a DRIVE STRENGTH gets none.

The Lhs follows the module home's already-gated netlist-re-elaboration rule
(a LITERAL or an OPERATION RHS gets a fresh net with its own deferred
typespec; a bare reference shares the listing net), and the listing net's own
typespec loses its net parent where a cell is minted — the identical rule
r10earl19 wrote for the gen-scope home, and the last two lines between the two
dumps on `q4_ndavar`.

### § caStrengthAndDelayDeclined88 (`R11U88_BOTH_OFF=1`)

> An `assign` carrying BOTH a drive strength and a delay is written by the
> producer in no view, so we mint no `cont_assign` for it — in the definition
> view, the elaborated module view, the elaborated interface view and the gen
> scopes alike, and for EVERY cell of a comma list.

Taken at the three LISTING sites (`emitContAssigns`'s `caOrder`, the
gen-scope loop, and r11u83's interface index walk), which keeps all three
mutually index-aligned; r11u83's length self-check would otherwise decline its
whole law on any interface that writes one (`z7_commaboth`).

### § caIfaceNdaNameFoldsToParamValue88 (`R11U88_FOLD_OFF=1`)

> A net-decl-assign RHS written as a plain NAME is substituted by that
> parameter's (or enum member's) own elaborated constant — value, decompile and
> constType verbatim, plus an instance-named `ref_typespec` onto the
> parameter's declared type — and the substituted copy alone takes the NET's
> width.

A name that resolves to no elaborated `param_assign` constant and to no enum
member keeps the `ref_obj` the builder already had: GOLDEN WRITES NOTHING ON A
MISS, and neither does this.  The parameter's own ts ref is bound LATE, so the
copy ALIASES it through `netTsAlias` — the seam `substNdaParamRefs` already
uses for the module home.

`R11U88_OFF=1` drops all three.  `R11U88_CELLDBG=1` traces every site both laws
reach — the DECLINED ones, the homes the gates exclude, and the MODULE home's
net-decl-assign population this pass deliberately does not touch — so ONE
traced run of ONE binary predicts each law's mover set a priori and censuses
the residue population in the same pass.
