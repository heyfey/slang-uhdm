R0 (default) — `flash_erase_ctrl.sv:42`, BankAddrMask's SHIFT AMOUNT.  ONE
OPERAND DEEPER IN THE SAME LAW:

    localparam logic[AddrW-1:0] BankAddrMask =
        ~(('h1 << (PagesBitWidth + WordsBitWidth)) - 1'b1);

    LHS (golden)                          RHS (ours)
      constant 42:57-42:70                  operation 42:57-42:86
      |vpiDecompile:16 |vpiSize:32          |vpiOpType:24 (vpiAddOp)
      |UINT:16 |vpiConstType:9              |vpiOperand -> constant UINT:8 sz32
                                            |vpiOperand -> constant UINT:8 sz32

  DECODE.  § elabParamOpLeafValueFold85 replaces IDENTIFIER leaves with the
  instance's stored Value; it does NOT reduce a sub-EXPRESSION that Surelog's
  own recursion folds.  `CompileExpression.cpp` compiles each operand with the
  caller's `reduce`, and the operand's OWN tail `reduceExpr` (:3648) folds
  `(PagesBitWidth + WordsBitWidth)` because nothing in THAT subtree is size(-1)
  — the bail is at the shift ABOVE it, not inside it.  `vpiAddOp`
  (ExprEval.cpp:3160) mints `UINT` at `max(sz0, sz1)` = 32, with NO typespec,
  which is exactly golden's cell.  So the next step is: inside a bail-kept
  tree, fold every MAXIMAL operand subtree that does NOT itself bail, using
  earl73's per-operator encoder tables for the value/size/constType, and keep
  the leaf rule for a bare identifier (the two producers give DIFFERENT
  typespec presence — see §4's r01 vs the add above).  ZERO extra corpus
  databases: the cells are BankAddrMask default and testflags.
