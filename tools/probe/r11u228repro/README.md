## 2. § memberInitReducedRootFolds228 (switch `R11U228_MEMROOTFOLD_OFF`, TypeEmit `makeTypespec`'s `resolveMemberInit`)

### 2.1 The face

v11u225's residue 1: a packed range bound that reads a localparam initialized by a member of a struct parameter
(`localparam int N = Info.x; logic [N-1:0] data;`). The base substitutes the member path for the localparam
(`[Info.x-1:0]`, the landed symbolic rule, decoded on a cast `info_t'(16)`) whatever the struct parameter's value is
written as. v11u225 measured that golden keeps the path only when the struct parameter is written as a cast or a typed
pattern; an untyped pattern, a plain integer or a concatenation is reduced, and golden's range holds the folded bound.
Case FO/g19 (`parameter info_t Info = '{x: 16};`), the base, parse view:

```
golden  range 6:10-6:17  left  constant 6:11-6:12  INT:15  size 64
base    range 6:10-6:17  left  operation 6:11-6:14 (Info.x - 1): hier_path Info.x 6:11-6:12, constant UINT:1
law     range 6:10-6:17  left  constant 6:11-6:12  INT:15  size 64
```

### 2.2 The law

In `resolveMemberInit`'s member-access branch, after the landed `r10fsv3 R-b` (an EvalFunc-built struct) and
§ memberInitBaseSelect (a base that is an element or range select) refusals: the struct parameter's root value (the
same bare-reference chain § memberInitBaseSelect follows) is read by its written syntax, through an implicit
conversion (`Info = 16` has no syntax of its own; the operand's is read) and through parentheses. When it is not a
`CastExpression` and not an `AssignmentPatternExpression` with a type, the member parameter is not substituted
(`resolveMemberInit` returns null), so the bound folds as every other parameter bound does. This is the syntax test of
§ fillSymbolicRootOnly225v (v11u225, TypeEmit), applied at the substitution itself. Traced as
`memberInitReducedRootFolds228 <member param> <struct param>`.

### 2.3 What stays

Every case the law moves stays stage 1: its next head is golden's typespec stamp on the elaborated `param_assign`
constants (the `16` of the pattern and the folded `N`, both given the declared `int` typespec of `N`: FO/g19 golden
`param_assign N` Rhs `constant 5:23-5:29 UINT:16` with `ref_typespec -> int_typespec 5:15`, ours without it). That
constant and its typespec are written by ParamEmit (the sister's ground): the call site is the elaborated
`param_assign` Rhs of a localparam whose initializer is a struct member (and of the struct parameter's pattern
operand), ParamEmit `emitParameters`, next to § paramValueIsDefRhs124. MR/m03 (a cast default overridden by an untyped

records golden holds under those param_assign stamps (section 8.2).

## 10. Fence and process

* **The fence.** Every driver reads the four names from canaudit.sh's `FENCED=` line and fails closed (drivers/env.sh,
  census.sh builds `--filter` from it for both corpora and downstream, bvmirror.sh skips fenced directories unread,
  case.sh refuses a path holding a fenced name, predict.py, awaycase.py and dscases.py refuse fenced rows). The gate
  sweeps dispatched every row as the gate mandates; only their csv verdicts were read for the fenced rows. No binary,
  gdb or script of this pass ran on a fenced test's sources or databases.
* **Process.** Early in the decode an unguarded `$UHDM_DUMP` in a shell without the environment made bash execute a
  golden database of FO/g19 (in this pass's own scratch); it stopped at a syntax error and wrote no file (the scratch
  directory listing checked). Every later dump went through `drivers/udump.sh`, which calls uhdm-dump by an absolute
  path after `[ -x ]`. One draft build failed (`any_cast` is not in the UHDM namespace) before any measurement; the
  binary copied from that attempt equalled d3 and was discarded. Every binary was frozen before it was measured; no
  source was edited while a translation unit compiled.
