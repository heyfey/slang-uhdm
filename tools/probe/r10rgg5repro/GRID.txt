MECHANISM (transcribed from UHDM templates/ExprEval.cpp): `list = '0` is a plain
assignment whose Rhs literal object BECOMES the array variable's value object,
exactly as § compoundLitWriteBackSat2's compound assignments do.  The tail's
`if ((c->VpiSize() == -1) && (c->VpiConstType() == vpiBinaryConst))` block stamps
that object's VpiSize from `ExprEval::size(lhsexp)` — ONCE.  Every later instance
finds VpiSize already set and re-uses the FIRST instance's width.  The
`(index*size_rhs + i) < si` bound in the element-write arm reads the same shared
`si`, which is why an N=2 instance in a design whose first instance is N=25 has
25 elements' worth of room and never escapes.

What decides it is how many demand-driven re-evaluations happen before that
instance's constant is minted — whether the doubling has reached the uint64
fixpoint yet — and r10rgg2 § 2 PROVED that count is not source-derivable (the
same body, one instance, N=25 gives 0 evaluations with only SUB_N_LIST present
and FIFTY-ONE once an int-typed NEXT_N is added).  This pass therefore claims
E0, states the Z list by name, and shows that NO CELL goes pristine-right ->
patched-wrong: on all 8 Z cells the base binary emitted the full multi-element
list, which is neither E0 nor Z.

  ALL THIRTEEN Rggen instances are on the E0 side (N=25 -> 4, N=2 -> 2,
  N=20 -> 4), and for N=2 and N=20 E0 == Z, so only the N=25 head instance
  actually rests on the claimed half.
