The nine arms, and what each one TESTS (not merely agrees with):
  a1_bases    every literal form on one untyped package parameter — 'h 'h0 'b
              'o 'd, signed 'sh 'sb 'so 'sd, unknown 'hx 'bz 'hz 'ox, SIZED
              32'h / 3'b / 3'bx, plain decimal, an expression, a parenthesised
              literal, a reference to another parameter, '0, and localparams;
              read back in four root edges (allModules/allPackages/topModules/
              topPackages) through a wildcard import.
  a2_typed    the FENCE: int / logic [7:0] / bit signed [15:0] / byte / string /
              signed / unsigned / [3:0] / integer declarations with the SAME
              unsized inits.  BYTE-IDENTICAL in both views — the typed shapes
              never enter the law.
  a3_homes    every home: $unit, package, interface, program, module body,
              module header, generate block, generate-FOR block, function,
              class.
  a4_over     overrides — named #(.O_P('hF)), positional #('hAB,'b11), defparam,
              and two DEFAULTED instances of the same overridable module.
  a5_ctx      the parameter used as a CAST SIZE, and a class parameter port.
  a6_edge     the 'b0/'b1/'B0/'B1 grammar tokens (size 0, NOT -1 — the fence),
              digit-separator underscores, an uppercase 'HF, macro-defined
              literals, a 19-digit hex, and a package parameter imported into a
              CLASS in another package (the UVM shape).
  a7_more     multi-declarator lists (parameter A='h1, B='h2, C='b11), a '?'
              digit, module ports, a modport interface, an instance override,
              a replication, and a parameter used as a vector width.
  a7v_more.v  the Verilog-2001 spelling, in a .v file.
  a8_toponly  parameters in a module that IS a top (never instantiated) — the
              arm that convicted the first draft: golden re-sizes a SIGNED
              based literal there (32) while leaving the unsigned ones at -1.
