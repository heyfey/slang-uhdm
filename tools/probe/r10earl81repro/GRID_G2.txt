WHAT THE GRID PROVES
  * SIX cells fold and ALL SIX land on golden EXACTLY, fields included.
  * NINETEEN cells are refused and NOT ONE of them moved (MOVED-WRONG 0).
  * uFa IS THE FENCE'S CONVICTION, not its excuse.  In a USER call's argument
    GOLDEN ITSELF KEEPS THE `ref_obj` (`compileTfCallArguments` compiles each
    argument with `pexpr = call`, and the identifier arm under a non-null
    `pexpr` binds through `bindVariable` and never reaches the `getValue`
    substitution).  Folding there would have been a MOVED-WRONG.  uFb is the
    SYSTEM-call half of the same split (§ genCaSysCallArgBinds22), and it DOES
    fold — which is why the gate tests `callArgDepth - sysCallArgDepth22`.
  * THE WIDTH IS THE WHOLE ENCODING STORY.  Every folded cell is size 64 — the
    raw unsized `Value` word — and every REFUSED cell golden renders at some
    OTHER width (32 for a declared `int`, 4/8 for a based literal or a narrow
    declared type).  A single "fold the parameter" rule without the
    overridden-bare-decimal fence would write 64 where golden writes 32 on 19
    of these 25 cells.
  * uW is the UNMASKED control: a bare decimal `20` bound to a `bit [3:0]`
    formal is golden `UINT:20` size 64, NOT the masked 4 the formal's type would
    give.  `collectParams_` stores `fromVpiValue(VpiValue, VpiSize)` with no
    `adjustSize` anywhere on that path.
  * `+TS` lands on exactly the SIGNED-`int_typespec` sub-case (uS `parameter
    int`, uZc `parameter signed [7:0]`, uZe `localparam int`) and on no other.
    That is a typespec-PRESENCE rule this pass MEASURED and deliberately did not
    take — R2 in PREDICT_R0.txt.

DIGIT NORMALISATION — measured separately, on g3_norm81.sv, because the producer
reads the actual's RAW TEXT:
  .Z(007)  golden UINT:7  sz64 ct9  dec `7`    (leading zeros stripped)
  .U(2_0)  golden UINT:20 sz64 ct9  dec `20`   (underscore dropped)
  patched reproduces BOTH exactly; pristine kept a `ref_obj` for each.
  The gate normalises the same way and then requires the re-evaluated value to
  render back to those very digits — which also refuses an unsized decimal too
  wide for slang's 32-bit literal type, whose Value Surelog would carry at a
  width this model does not name.
