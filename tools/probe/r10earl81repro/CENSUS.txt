4. THE 64-vs-32 SPLIT IS THE LAW'S CORE, and golden states it
========================================================================
  OVERRIDDEN at the instantiation  -> the stored Value keeps the ACTUAL's own
      encoding AND WIDTH; a bare decimal is Surelog's unsized 64.
  NOT overridden                   -> `adjustSize` runs BEFORE the capture, so
      the Value already carries the DECLARED type's width (32 for `int`).
  Golden's own `param_assign` for the head's N in the head's instance is
  `UINT:2 size 32`, so COPYING THE param_assign WOULD BE A NEW WRONG ANSWER AT
  EXACTLY THE HEAD.  The fold reads the instantiation's actual, not the
  parameter's own constant.
