===================== arms/v188_h_negsize.sv — A MEASURED, UNTAKEN RESIDUE =====================
The patch ABSTAINS when the modelled size goes below zero (`a188.size >= 0`),
because that case was Surelog-reachable but unmeasured.  It is now measured, on
one real Surelog golden, seven right shifts each in its own typedef (a shift past
the left operand's width always evaluates to 0, and an enum's members must differ):

  shape          golden DEF SZ   golden FOLDED SZ   ours (fix)
  8'hFF >> 9         -1                64            abstains -> 64 / DEC empty
  8'hF0 >> 10        -2                64            abstains -> 64 / DEC empty
  8'hE0 >> 12        -4                64            abstains -> 64 / DEC empty
  4'h8  >> 12        -8                64            abstains -> 64 / DEC empty
  4'h8  >> 5         -1                64            abstains -> 64 / DEC empty
  8'hFF >> 8          0                64            MATCHES golden exactly
  8'hFE >> 7          1                64            MATCHES golden exactly

Golden publishes the RAW negative number, not a clamp and not the unsized marker.
Dropping the guard would take 10 more cells TO-GOLDEN with no rule change at all.
The verifier deliberately did NOT take them: the brief's fix mandate is
pristine-right -> patched-wrong, this is pristine-wrong -> patched-wrong, the
corpus population is ZERO (byteverify: the only moved databases are BuildUVMPkg
x2, whose shapes are all `1 << N`), and an unmeasured widening is exactly what
produced the defect in § 2.  Handed forward with its numbers instead.
