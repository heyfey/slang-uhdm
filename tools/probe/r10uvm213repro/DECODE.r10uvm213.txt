=== 1. WHAT THE JUDGE READS

~/git-repos/UHDM/build/generated/src/typespec.cpp:80-95

    int32_t typespec::Compare(const BaseClass *other, CompareContext* context) const {
      ...
      if ((r = lhs->VpiName().compare(rhs->VpiName())) != 0) { ...; return r; }
      if ((r = SafeCompare(lhs->Typedef_alias(), rhs->Typedef_alias(), context)) != 0) return r;
      if ((r = SafeCompare(lhs->Instance(),      rhs->Instance(),      context)) != 0) return r;
      return r;
    }

`Instance()` is a typespec's back-pointer at the scope it belongs to, and
SafeCompare on two non-null pointers is a FULL compare of the pointees.  So a
placeholder whose back-pointer names the WRONG VIEW of a package hands the
judge that whole package: golden's DEF listing against our ELABORATED one, two
listings that legitimately differ.  Nothing in the cmp log says this happened —
it prints the failed pair and no route (r10uvm210 §3, which named the crossing
and left the repair as its R0; this pass is that repair).

No generated Compare reads VpiParent, so the SHARING of a placeholder is
invisible to the judge — but its arity is not, because each holder reaches its
own copy.

=== 2. WHAT SURELOG WRITES — PER-VIEW COMPILE, PER-VIEW INSTANCE

    CompilePackage.cpp:213-218 — `paFunction_declaration` (and :205-211,

(c) THE PLACEHOLDER TAKES ITS COMPILE'S OWN COMPONENT.

    A type-parameter name (`REQ`) reaches that catch-all — the class's data-type
    table cannot answer it while the package is being compiled — and is minted

(d) AND THAT COMPONENT'S UHDM OBJECT IS THE `AllPackages` ENTRY.

=== 3. WHERE WE WROTE IT WRONG

Our package CLASSES ride the ELABORATED view only (`emitPackageClasses`,
src/UhdmExporter.cpp:2841-2861, called from `emitPackage` under `if (topView)`,
src/ParamEmit.cpp:23286-23289).  The DEF listing is then built by
`emitPackageClassMethodClones` (src/ParamEmit.cpp:23386-23444), which re-runs
`emitTaskFuncs` over the SAME class_defn with `pkgClassTfClone` set to the DEF
package.

`oobDeclPkg31` — the pointer § oobParamClassTypeParamFormalUnsupported31 (the
FORMAL site, src/TaskFuncEmit.cpp ~4841) and
§ oobClassTypeParamLocalUnsupported105 (the BODY-LOCAL site, ~6267) stamp their
placeholders with — was read off the class_defn:

        if (auto* hp31 = ((UHDM::class_defn*)m)->VpiParent();
            hp31 && hp31->UhdmType() == UHDM::uhdmpackage)
            oobDeclPkg31 = (UHDM::instance*)hp31;

and a class_defn's VpiParent is the TOP package in every listing, because there
is only one class_defn.  So both views got the ELABORATED twin.

Everything ELSE in that same def listing was already view-correct: the
`tsInst` / `pkgScopeInst` pointer the other placeholder laws use (§ 11, § 34,
§ 105's siblings, § 115, § 155) is the listing's own package, which r10uvm183
recorded ("the home package's own two views are untouched ... `pkgScopeInst` is
already the answer golden gives: its own def copy in the def view").  The
corpus reading confirms it: 1180 of our def-listing typespec copies already
carry `ALLPKG:uvm_pkg` on SeqDriver, against golden's 1172.

=== 4. THE FIX, AND WHY EACH CONJUNCT

    if (pkgClassTfClone && !pkgImportCloneEmit &&
        (UHDM::BaseClass*)pkgClassTfClone != hp31 &&
        pkgClassTfClone->VpiName() == hp31->VpiName())
        oobDeclPkg31 = (UHDM::instance*)pkgClassTfClone;

  * `pkgClassTfClone` is non-null in exactly two drivers (grep: it is assigned
    at src/ParamEmit.cpp:23403 and :23805 and nowhere else).
  * `!pkgImportCloneEmit` picks the first of them —
    `emitPackageClassMethodClones`, the HOME package's own DEF listing.  The
    second, `emitImportedPkgClassMethodClones`, sets `pkgImportCloneEmit` and
    must keep the ELABORATED home (§ 2(e)).
  * `!= hp31` makes the stamp a NO-OP on the elaborated listing, where
    `pkgClassTfClone` is null anyway — belt and braces, and it documents that
    the two views take two different pointers.
  * the NAME test refuses any future driver that points `pkgClassTfClone` at a
    package that is not this class's own home.

Nothing is minted, nothing is removed, no name is written, one pointer moves.
