              package home, bare-decimal init) read from FOURTEEN consumers:
              a packed range on a struct-array var, on a net, on a var, with
              the parameter on the RIGHT; an unpacked SIZE-form dim; an
              unpacked RANGE-form dim; a packed range in a typedef and an
              unpacked one; a part-select bound; an expression operand; a
              bit-select index; a replication count; a port High_conn; a user
              call argument; a case item; a cont-assign RHS; an indexed
              part-select base.  RESULT: golden answers 32 at EVERY one of
              them, and OUR EMITTER ALREADY ANSWERED 32 at every EXPRESSION
              consumer — the gap is the RANGE consumers alone.  That is what
              made this a range law and not an expression one.

g3_shape82.sv THE BOUND-SYNTAX AXIS.  `[P:0]` bare / `[pkg::P:0]` qualified /
              a module localparam / an untyped one / `[P-1:0]` / `[P+1:0]` /
              `[P*2:0]` / `[$clog2(P)-1:0]` / `[P:Q]` both bounds / `[7:0]` a
              written literal / `[(P):0]` parenthesised.  Golden folds an
              ARITHMETIC bound to `reduceExpr`'s own value at 64 and we already
              match on every one; a written literal is 64 on both sides.  The
              law therefore fires on a PLAIN identifier bound only, and this
              arm is why.
