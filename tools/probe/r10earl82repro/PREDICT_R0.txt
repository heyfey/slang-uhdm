RANKED RESIDUES this pass MEASURED and deliberately did not take
========================================================================
R1  THE BASED-LITERAL PARAMETER AT A RANGE BOUND.  `localparam bit [3:0] P =
    4'h7` is golden `HEX:7 sz4 ct5` and `localparam int P = 8'd8` is golden
    `INT:8 sz8 ct7` at EVERY range consumer; we write `UINT:7 sz4 ct9` and
    `UINT:8 sz32 ct9`.  The value AND the constType move with the width, so a
    size-only law cannot take it — it is r10earl80's `SrlgLitEnc`/
    `srlgAdjustSize` producer/consumer pair applied at a THIRD consumer.  Both
    fences are written by name in `ovActualStoredWidth82` and
    `pkgVarDimBoundEnc82`.  g5 cells PKD, PKV, NOD, NOV, OVV, OVH, LPV, LPB.
    Cheapest of the residues because the encoder already exists.

R2  THE UNTYPED PARAMETER'S STORED WIDTH IS TWO-FACED.  g5's PKU (`localparam
    PKU = 8` in a package) is golden sz32 on the TYPESPEC copy of a bound and
    sz64 on every other copy of the same written dimension; the module-scope
    twin LPU is golden sz32 everywhere.  There is no single width for an untyped
    parameter, so this pass refuses them all and leaves them byte-identical.

R3  THE DECLARATION-SIDE COPY OF A **MODULE**-PARAMETER BOUND IS A DIFFERENT
    OBJECT, NOT A DIFFERENT WIDTH.  On g5's whole `packed-structarr-var` column
    golden emits `3 x ref_obj` (the DEF listing) + `6 x constant`, and we emit
    `9 x constant`: the DEF listing should keep the symbolic ref the way
    § patDefBoundPkgParamSubst's module half already does on the TYPESPEC copy.
    That is a KIND law, and until it lands a size fix on that column could only
    move cells that cannot reach golden — which is why `pkgVarDimBoundEnc82`
    refuses every non-package referent.

R4  THE `ct` FIELD AT A DECLARATION-SIDE BOUND OVER AN ARITHMETIC PACKAGE
    PARAMETER.  `r10vearl74repro/va2_v74.sv:34` (`logic [D:D+3] s_updn`, `D`
    overridden 20 ways) has golden `INT:8 ct7` on 12 of its cells where we write
    `UINT:8 ct9` in every state.  This pass moves that row's SIZE strictly
    CLOSER to golden (multiset distance 30 -> 18, measured) and leaves the
    encoding exactly as it found it; `paramIntEnc` is the model that would
    finish it.

R5  AN ADDRESS LEAKS INTO A CONSTANT'S VALUE (earl81's R5, RE-MEASURED HERE AND
    STILL LIVE).  `tools/probe/r10buvm22repro/g22.sv` emits a constant whose
    `vpiDecompile`/`UINT` differs by EXACTLY 4128 between two binaries of
    different size.  Convicted as NOT this law by the kill switch: with
    `R10E82_OFF=1` the patched binary STILL differs from pristine on that file
    (`attr82.sh`: `neutral != pristineA`), while each binary is stable against
    itself.  It is the tax every per-directory boundary walk pays.
