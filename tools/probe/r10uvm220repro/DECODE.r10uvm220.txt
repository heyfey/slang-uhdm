WHY writeInstance ALSO fixes the DEF view (arm a3, arm a2)
-----------------------------------------------------------
`lateTypedefBinding` MUTATES the objects on `mod->getLateTypedefBinding()`,
which are the DEFINITION-phase objects.  So one instance is enough to resolve
the definition listing too — which is exactly what arm a2 (`if220i`, the same
body instantiated) and arm a3 (`m220sub`, a module) measure: every cell
resolves in BOTH views.  And a module with no instantiator is a TOP, hence
always elaborated, so there is no uninstantiated MODULE to test — the holder
this law needs can only be an interface or an uninstantiated program.
