The patch AS SHIPPED introduces a SEGFAULT on legal SystemVerilog.

  minimal repro (v93_crash_min.sv):
      module m1;
        byte q[];
        bit [63:0] f;
        initial begin
          { << real { q }} = f;
        end

      pristine b1a0447   -elabuhdm  ->  rc=0, database written
      r10uvm93 AS SHIPPED -elabuhdm ->  rc=139 SIGSEGV, NO database
      verified patch      -elabuhdm ->  rc=0, database written

  stack (gdb, binary fc58485a):
      UHDM::ExprEval::reduceExpr
      UHDM::UhdmAdjuster::updateParentWithReducedExpression
      UHDM::VpiListener::listenSys_func_call
      ... listenOperation <- listenAssignment <- listenBegin <- listenInitial
      ... listenModule_inst <- listenDesign

  ROOT CAUSE.  UHDM/templates/ExprEval.cpp:4389 handles
  $bits/$size/$high/$low/$left/$right with

      for (auto arg : *scall->Tf_call_args()) {

  — an UNCONDITIONAL dereference.  The pass's new time/realtime/real/shortreal
  branch emits a `$bits` sys_func_call with NO Tf_call_args (faithfully copying
  Surelog's compileBits, which also leaves it null).  During `-elabuhdm` our
  UhdmAdjuster walks every sys_func_call, and the null vector is dereferenced.
  Surelog itself never survives its own UHDM elaboration of this shape (it dies
  in the same place — that is why arm v93_a1_types.sv has NO elab golden), so
  golden could never have exposed it.  The corpus cannot see it either: no
  corpus source has a real/time slice size (verified by the source scan in §5),
  and verify_golden.py records rc=139 as SLANG_REJECT wearing the last stderr
  warning — so this would have landed as a silent landmine.

  THE FIX (src/ExprEmit.cpp, 1 statement + comment):

      sf->Tf_call_args(s.MakeAnyVec());     // EMPTY, non-null

  It is JUDGE-INVISIBLE.  BaseClass.h's vector SafeCompare overload reports a
  mismatch only when the NON-NULL side is NON-EMPTY:

      } else if ((lhs != nullptr) && !lhs->empty() && (rhs == nullptr)) {
      } else if ((lhs == nullptr) && (rhs != nullptr) && !rhs->empty()) {

  so golden's null and our empty vector compare EQUAL.  Proven, not argued:
  arm v93_c1_bitsfall.sv (real/realtime/shortreal/time slice sizes in package
  function, class method x3, interface, module initial, always_comb and a
  generate block) is CMP_FAIL on pristine and **CMP_EQUAL on the fixed binary**,
  against the official uhdm-cmp.  And on both corpora the fixed binary's
  databases are BYTE-IDENTICAL to the shipped patch's (§4).

5. RANKED RESIDUES (all measured, none of them regressions)
================================================================================
R1  raw-text scan finds the WRONG `<<`.  `emitExpr` searches the whole streaming
    expression's raw text for the first "<<" (then ">>"), so an inner shift in a
    stream OPERAND captures the scan:
        golden                          ours (pristine AND patched, identical)
        { >> byte { v << 2 } }   8      LOCATED constant 2
        { >> 8    { v << k } }   8      LOCATED constant k
    PRE-EXISTING, unchanged by this pass, and the highest-value residue here
    because it silently emits an operand token as a slice size.  Fix: find the
    stream operator at the START of the expression (after the opening `{`),
    never by an unanchored search.  Arm v93_b3_nest.sv.

R2  macro-ARGUMENT slice size.  `rawText` reads the macro BODY, so the token is
    the macro PARAMETER name.  golden 32 / pristine `T` / patched 0 — both wrong.
    Disclosed by the pass.  Note the patch IMPROVES the sub-case where the macro
    argument is a typedef (golden 0, patched 0).  Arm v93_a7_macro.sv.

R3  a COMMENT between the type token and the stream `{` defeats the wholeSlice
    test:  `{ << int /*c*/ { v } }` -> golden 32, ours `int` (pristine spelling).
    And `{ << /*c*/ int { v } }` -> ours `/*c*/` (pre-existing).  Newlines and
    tabs are handled correctly.  Arm v93_a8b_layout.sv.

R4  parenthesised / compound slice size `(WREN+2)`, `WREN + 2` -> golden emits a
    LOCATED operation, we still emit a spelled constant.  Disclosed by the pass;
    untouched.  Arm v93_a3_num.sv.

R5  sized numeric slice size `8'd4` -> golden vpiSize 8 / vpiConstType 1; we emit
    vpiSize 64 / vpiConstType 9 with decompile `8'd4`.  PRE-EXISTING, untouched.
    Arm v93_a3_num.sv.

R6  UHDM UPSTREAM (not ours, not fixable here): ExprEval::reduceExpr dereferences
    Tf_call_args() without a null check for $bits/$size/$high/$low/$left/$right.
    Surelog trips it too — `surelog -elabuhdm` dies on a real/time slice size, so
    no elaborated golden for that shape can exist.  Worth an upstream report.
