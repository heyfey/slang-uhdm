ARM 1 — the SEPARATOR matrix.  `define S_X `"`N``X```MA``.```MI```"` with
N=ABC, MA=1, MI=2 and X one of  -  _  .  :  /  x  7  ,  *  +  <space> .
GOLDEN gives `ABC.1.2` for EVERY ONE of the eleven.  Two negative controls in
the same package: `` `"`N-`MA.`MI`" `` (no paste) stays `ABC-1.2` and
`` `"hello world`" `` stays `hello world`.  This is the whole law: the
character between two pastes is not preserved, not deleted — it is REPLACED
BY A DOT, because Surelog's replacement pattern is the string "``.``" used as
an ECMAScript REGEX and its `.` is an unescaped wildcard.

  `"`Q``-`R`"           paste, char, ONE backtick     ABC-1      unchanged
  `"`Q``--```R`"        TWO characters between        ABC--1     unchanged
  `"`Q``ab```R`"        TWO characters between        ABCab1     unchanged
  `"``-`Q`"             paste at the string START     -ABC       unchanged
  `"`Q-``    `"         paste at the string END       "ABC- "    unchanged
  `"`Q``-`R``.`T`"      pastes abut MACRO REFS only   ABC-1.2    unchanged

  `"`Q``-``R`"          bare word after the paste     ABC.R
  `"pre``-``post`"      no macro at all               pre.post
  `"xx``-``yy`"         no macro at all               xx.yy
  `"`Q``-```R``.```T``-```Q```"   three matches       ABC.1.2.ABC

CORRECTION (verifier r10v104, arms v2_args_coincide / v13_argnofml, both
views).  This arm passes for the WRONG REASON, and the parenthetical it
originally carried — "the definition text still names the formals, so the
alignment mismatches on the first literal and bails" — is FALSE.  The
alignment mismatches only because `PAIR(int,bit)` / `AA(byte,shortint)` pass

definition text lines up byte-for-byte with the value, both walks agree, and

pristine build) have `A(B)`, `aa(V,I)` and `a-b`: 36 cells AWAY-FROM-GOLDEN
