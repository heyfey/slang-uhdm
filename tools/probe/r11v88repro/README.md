### 2a. THE ONE BREAK — fixed here

`v2_enumshadow` / `v26_pkgvecshadow`, both `golden_rc=0 ours_rc=0`:

```systemverilog
package pk; typedef enum logic [3:0] { EA, EB = 2 } e_t; endpackage
interface ifc ();
  localparam int EB = 9;
  wire [31:0] w_e = pk::EB;
endinterface
```

golden `|vpiDecompile:2 |vpiSize:32 |UINT:2 |vpiConstType:9`, the patch as
submitted `|vpiDecompile:9 |vpiSize:32 |UINT:9` **plus** a
`ref_typespec (work@dut.u_if)` onto the interface parameter's `int_typespec`.
LAW C scanned `iface->Param_assigns()` for `Lhs()->VpiName() == nsym88.name`,
and a package enum member read through `pk::` carries the bare name `EB`.

THE FIX (one predicate, in the same gate): an `EnumValue` symbol is never one
of this interface's `param_assign`s, so it takes the enum branch.  The MODULE
home is not affected — `pk::EB` folds there before `substNdaParamRefs` ever
sees a `ref_obj` (`v25_enumshadowmod`, `cmp_rc = 0` on both binaries).  The
fix is **byte-inert on all 73 implementer arms** (all 73 dump bodies identical
between the two law binaries) and converts the two arms above.

## 5. RESIDUES THIS VERIFICATION ADDS (ranked, all measured, none a regression)

1. **THE SUBSTITUTED VALUE IS NOT TRUNCATED TO THE NET** (`v15_ndaparamnarrow`,
   `localparam int K = 300; wire [7:0] w_tr = K;`): golden re-encodes to
   `UINT:44 dc 44 sz 8`, LAW C copies the value verbatim and only resizes —
   `UINT:300 dc 300 sz 8`.  LAW C's "verbatim" rule holds only while the value
   FITS; the grid's parameters all fit.
2. **A SIZED 64-BIT LITERAL IS RESIZED TO THE NET** (`v3_wide64lit`,
   `wire [31:0] w_64 = 64'd5;`): golden keeps `vpiSize 64`, we write 32.  The
   `VpiSize()==64 -> net width` heuristic cannot tell a bare decimal from a
   written `64'd…`.  **INHERITED, not introduced**: the MODULE home carries the
   identical rule and the identical DIFF on both binaries (`v24_wide64mod`,
   `DIFF -> DIFF`, byte-identical pristine and law).
3. **LAW C IS WHOLE-RHS ONLY** (`v16_ndaexprops`, `wire [31:0] w = 32'(K);`):
   golden folds the inner name to a constant inside the cast operation, we keep
   `ref_obj K`.  The module home's `substNdaParamRefs` recurses into operations;
   the interface builder substitutes only when the whole initializer is a
   `NamedValue`.
4. **THE NET DECLARATION's PARAMETER DELAY** (`v22_ndadelayparam`,
   `wire [31:0] #D w = …`): golden folds `constant UINT:3 sz 32` with the
   parameter's instance-named `ref_typespec`, we write
   `constant UINT:0 dc #D sz 64` — the same class as the pass's own R3
   (`z2b_delayref`), now measured on the DECLARATION delay too.
5. **A STRUCT / non-`logic_net` NET-DECL-ASSIGN GETS NO CELL** (`v4_structnda`):
   golden lists one, LAW A's holder fence passes it over.  `v4`'s cmp line
   count rises 105 -> 171 on the SAME head object (the interface_inst `vpiNet`
   vector) purely because the head's printout now contains the correctly added
   `w_nd` cell; set-wise AWAY 0 and no cell moved from MATCH.
6. **LAW B's DEF-VIEW GEN-BLOCK STATEMENT is not covered** (`v10_bothgenfor`):
   the module def view's gen-block `|vpiStmt:` still carries the declined
   `cont_assign` (line `16:32`), where golden's block ends at the variable
   `assignment`.  The interface's def-view gen block does decline.  Pre-existing
   ours-only object in both binaries' gen-scope listing; the arm's head is
   byte-identical on the two binaries.
