2. THE SURELOG DECODE -- the substitution rule, read out of the source
===============================================================================
`CompileHelper::compileExpression`, the simple-identifier arm,
Surelog/src/DesignCompile/CompileExpression.cpp:2918-2975:

    if (component && (result == nullptr))
      if (VectorOfparam_assign *pas = component->getParam_assigns())
        for (param_assign *param_ass : *pas)
          if (param_ass->Lhs()->VpiName() == name)
            if ((reduce == Reduce::Yes) || (paramFromPackage && const Rhs))
              if (substituteAssignedValue(param_ass->Rhs(), compileDesign)) {
                result = UHDM::clone_tree(param_ass->Rhs(), &elaboratorContext);
                result->VpiParent(param_ass);
                fC->populateCoreMembers(child, child, result);   // the READ's span
              }
    ...
    if (result == nullptr) { ref = s.MakeRef_obj(); ... }          // what WE emit

i.e. a CLONE of the parameter's own `param_assign` Rhs, re-parented at the
`param_assign` and re-anchored at the READ's span; the `ref_obj` we emit is
that arm's `result == nullptr` fallback thirty lines below.  A clone carries
the source constant's ENCODING and its TYPESPEC.  `substituteAssignedValue`
(CompileExpression.cpp:83) only ever refuses a concat / assignment-pattern
operation when `--parameterssubstitution` is off, which it is not here.

NOT `UhdmWriter::writeCont_assign` (UhdmWriter.cpp:2090): that path reduces a
cont_assign Rhs only when `bindVariable` finds the Lhs, and `bindVariable`'s
scope-walking overload (CompileStmt.cpp:3089) switches on function / task /
begin / module_inst ONLY -- from a `gen_scope` it falls through to the
enclosing `module_inst` and NEVER finds a gen-LOCAL declaration, which
`sleep_mux` is.  The substitution is the GENERATE ELABORATION's, compiled with
`Reduce::Yes`, which is also why the DEF view keeps the `ref_obj` on both
sides (measured: h1's DEF row is SAME).
