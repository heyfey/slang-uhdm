# v11u193: adversarial verification of r11u193 (pair B, the module/type ground)

Verdict: **ACCEPT-WITH-FIX**. Every headline number of r11u193 reproduces bit for bit. 77 fresh cases found no case
where pristine was right and the patch is wrong. One transcription error (a package-qualified `::` rewritten to `.`)
and two coverage gaps are refined behind their own switches (§3). The refinements add one probe conversion, the one
the predictor named before the sweep, and move no corpus byte.

Base `6ab9f4fb` (branch matrix-1.87, pass 188). Implementer patch `r11u193.patch`: `src/ModuleEmit.cpp`,
`src/UhdmExporter.cpp`, `tests/LAWS.md`, `tools/probe/r11u193repro/`. The verified patch adds three refinements (§3) in
the same two files, plus this directory. No line of the sister's files (`src/ExprEmit.cpp`, `src/EmitHelpers.h`,
`src/StmtEmit.cpp`, `src/ParamEmit.cpp`), `include/`, `scripts/`, `results/`, `tests/probe/` or `third_party/` is
edited. `tests/LAWS.md` is regenerated by `python3 scripts/law_index.py`.

**The fence.** The four fenced names are read from the `FENCED=` line of `tools/probe/r11u107repro/canaudit.sh` by
`drivers/env.sh`, which fails closed. Every driver refuses them by word boundary. Byte comparisons ran on hard-link
mirrors that leave them out (`fenced_skipped=8` per sweep), and the predictor scanned the same mirrors. No fenced test
was run, read, scanned or decoded outside the gate sweeps, and gdb was not used.

## 3. Findings and the refinements (each droppable alone; `R11V193_OFF` or `R11U193_OFF` drops all three)

`v11u193Law(sw)` (UhdmExporter.cpp, beside `r11u193Law`) reads the switches.

| switch | law | file | case (first line names the law) |
|---|---|---|---|
| `R11V193_NESTPKGQ_OFF` | § nestChainKeepsPkgQual193v | UhdmExporter.cpp (`nestedDefChainName193`'s rename) | `cases/NN/nn01_pkgref` |
| `R11V193_NESTSEL_OFF` | § nestChainSelects193v | UhdmExporter.cpp (same) | `cases/NN/nn06_genfor` |
| `R11V193_UCRANGE_OFF` | § ucCloneUnnamesRanges193v | ModuleEmit.cpp (`unsizedRhsCloneDrain193`) | `cases/UC/uc08_widthparam`, `cases/UC/uc16_tn_widths` |

1. **§ nestChainKeepsPkgQual193v: a transcription error of § nestedDefChainName193.** The law rewrites *every* `::`
   in the rest of the name to `.`. A `::` that qualifies a package belongs to a component's own name, though, such as
   the enum typespec `pk::e_t` that a base-typespec reference inside a nested definition is named through.
   * Golden: `work@sub.work@sub::inner.pk::e_t`
   * law.bin: `work@sub.work@sub::inner.pk.e_t`
   * pristine: `work@sub::inner.pk::e_t`

   Pristine was wrong too, so this is not a regression. It is a wrong value on a shape the law claims.
   **Refinement**: a `::` whose preceding identifier names a package (the design's `AllPackages`/`TopPackages`) is
   kept. nn01_pkgref goes `fullname(18)` pristine -> `fullname(3)` law -> **EQUAL**.
2. **§ nestChainSelects193v: a coverage gap.** The rename's type switch skips the selects: `i[k]` inside a nested
   definition's generate block keeps `work@sub::inner.g.i` (golden `work@sub.work@sub::inner.g.i`). **Refinement**:
   bit, part, indexed-part and var selects (all `ref_obj`s) take the rename. nn06_genfor goes `fullname(19)` ->
   `fullname(2)` -> **EQUAL**.
3. **§ ucCloneUnnamesRanges193v: a coverage gap.** The clone is whole, but `unname` does not descend into a part
   select's bounds or an indexed part select's width. In `y[W-1:0]` the `W` keeps the definition's `work@m.y.W`
   (golden `work@top.u_a.y.W`). **Refinement**: descend into `Left_range`/`Right_range` and `Width_expr`, clearing only
   names derived from the definition as before. uc08_widthparam goes `fullname(5)` -> `fullname(2)` -> **EQUAL**, and
   uc16_tn_widths goes `fullname(5)` -> `fullname(4)` -> **EQUAL**.

## 5. Residues, ranked

1. **Two or more outside writers of one package typedef** (pm01): golden's import copies are snapshots, reading the
   span of the last writer compiled before the importer. § tfArgQualOutsideWriter176 declines on this shape, so
   § tfArgOutsideCopyOrder193 never fires. Site: the UhdmExporter mover, § tfArgOutsideCopyOrder193.
2. **Package-internal references to a moved typedef** beyond the parameters (pm07: `typedef s_t pair_t [2]`'s element
   reads moved in golden, the declaration in ours). Site: the same mover's branch (a).
3. **Cast leaves in interface-instance and bind connections**: CL/s12 (`emitInterfaceInstance`) and bc09
   (`bind ... (.d(7'(r)))`). § connLeftmostLeafElab139's walk is not run there. Site: ModuleEmit.
4. **Interface continuous assignments**: the fill-branch and unsized-clone legs are not modelled (tf07, uc22).
5. **Golden's unsized detector sees behind references and typespecs** (VpiListener `vpiActual`, `vpiTypespec`), so
   golden clones in cases ours does not.
6. **Member access inside a cast actual** (bc23: `r.b` named `work@dut.b`, golden `work@dut.u.d.b`). This is the
   hier_path naming in ExprEmit, the sister's ground.
7. From r11u193's own list: ibex_pmp `#13972`, a generate-scope var_select typespec (ExprEmit `emitExpr`, the
   sister's); the r11u115 generate-scope substituted package-parameter typespec name (22 probe cases, the expression
   emitter); r10rgg9 c_iface_body / c_paraminit / l_concat; nested module arrays and program instances (v11u93 b07,
   r11u105 k40/k42, r11v105 v13/v22).
