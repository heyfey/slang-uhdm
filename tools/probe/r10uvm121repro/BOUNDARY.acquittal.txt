---- 3. TWO INSTRUMENT NOTES, both paid for here

* The ARM scorer (armcen121.py/score121.py) counts DUMP-TEXT prints, and
  uhdm-dump prints an object once per PATH it is reached through.  In the ELAB
  view, removing one subtree changes how many times UNTOUCHED objects are
  re-printed, which the arm scorer reads as a changed cell (v2_copy elab shows
  three such cells over PLAIN `lp = new gp;` targets that no predicate of this
  pass can even see).  The table above therefore uses ct121cen — DISTINCT
  reachable objects — and the arm scorer is kept for the DEF view and the grid,
  where one object is reached once.
* `uhdm-dump --stats` is NOT a stable instrument here: it counts every
  serializer object, reachable or not, and three runs of the ONE pristine binary
  on r10svs3repro/a4_ctorspan.sv gave three different stat blocks while the
  DUMP TREE was byte-identical across all three.  Only the dump tree (what the
  judge walks) is deterministic per binary.
