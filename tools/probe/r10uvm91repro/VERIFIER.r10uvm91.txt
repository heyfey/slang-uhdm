=== 4. THE LAW AS IT NOW STANDS ==========================================
A class holds ONE typespec per DEFAULT-CHAIN ROOT among its own type parameters.
The object is built from the ROOT parameter's class-header default; it is NAMED
for the BYTE-WISE ALPHABETICALLY LAST candidate typedef of the chain; and every
member of the chain binds it — each type_parameter, and the FIRST candidate
typedef of each member.  A typedef written with DIMENSIONS is an array_typespec
OVER the parameter and is not a candidate; a local/protected typedef is not a
candidate; a typedef-of-a-typedef CONSUMES its target.

Independently re-confirmed by the verifier, each on a cell the implementer's
grid does not carry (`v91_a1_kinds.sv`, `v91_a2_scope.sv`):
  * chains 5 deep with the only typedef on the MIDDLE parameter (`c_chain5`)
    and on the FIRST and LAST (`c_chain5b`) — correct.
  * typedef-of-typedef 2 and 3 deep (`c_tdtd`, `c_tdtd3`) — correct; and
    `c_tdtd2`, where consumption leaves a parameter with NO surviving candidate,
    correctly stays ANONYMOUS exactly as golden does.
  * `local` on the LAST typedef of a chain (`c_qmix`, golden `a_t`) and on the
    FIRST (`c_qmix2`, golden `b_t`) — correct in both directions.
  * kinds: integer / time / longint / shortreal / reg — all correct.
  * scopes: $unit (`cu_unit`), a NESTED class (`c_outer::c_inner`), a derived
    class with its OWN parameters (`c_pderi`), and a derived class whose base
    specialization uses its own parameter (`c_pderi2`) — all correct.
  * specializations: Surelog compiles a parameterised class ONCE, generically,
    so partial (`c_p3 #(bit)`), full, int->class and class->int specializations
    produce no separate type_parameter cells in golden either.  No divergence.
