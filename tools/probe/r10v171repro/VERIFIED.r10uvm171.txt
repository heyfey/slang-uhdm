  a reallocation, and the patch adds no new lifetime exposure.
* `pkgImportCloneEmit` is ALSO true in `emitImportedPkgClassMethodClones`
  (ParamEmit.cpp:23180), so a class-method clone DOES fill `selRefs171`.  It is
  harmless: that path sets `pkgImportCloneRetVar = nullptr`, so `pf.bindVar` is

  objects are dropped — which is what golden wants (arm v171_c_homes.sv: the

  11-element aggregate initialiser at TaskFuncEmit.cpp:6374 still lines up field

* The pool is disjoint from `refs`, so the collected objects never reach
  `drainFuncRet`'s per-reference local mint, nor `classRetNameRefs37`, nor
  `retNameRefs56`.  That last one matters: `retNameNoBind56`'s law B UNBINDS any
