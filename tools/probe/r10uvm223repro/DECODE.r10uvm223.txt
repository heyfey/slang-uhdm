3. THE PRODUCER, DECODED FROM SURELOG SOURCE
--------------------------------------------

`CompileHelper::importPackage`, src/DesignCompile/CompileHelper.cpp:127-197.
Its Nets arm, :183-190:

    auto& netSet = def->getSignals();
    for (auto& net : netSet) {
      if (!object_name.empty()) { if (net->getName() != object_name) continue; }
      scope->getSignals().push_back(net);
    }

  * `scope` is the IMPORTING `DesignComponent`.  The function asks NOTHING
    about the holder's kind.
  * `object_name` is empty for a WILDCARD import and is the named symbol for an
    EXPLICIT `import p::name` — which is why an explicit import materialises
    exactly one entry (grid arm a2).
  * it PUSHES INTO A VECTOR, so the entries ACCUMULATE and are never
    de-duplicated: a package that imports a package carries the inner
    package's entries onward (arm a6), and importing both ends of the chain
    lists the inner one TWICE (arm a5) — which is exactly the corpus shape.

WHO CALLS IT FOR AN INTERFACE.  An interface is a `ModuleDefinition` in
Surelog and goes through `CompileModule`.  `collectModuleObjects_` runs the
`paPackage_import_item` arm at src/DesignCompile/CompileModule.cpp:600-604
(and again at :1086-1090 for the second collection road), and BEFORE the walk
it runs the FILE-scope pre-pass at :570-580 / :1060-1070, which imports every
`paPackage_import_item` the FileContent carries.  That second road is the
compilation-unit import, and it is why a file-level `import p::*` materialises
the listing TWICE while a body-level one materialises it once (arm a8; the
multiplicities are § collectMaterializedPkgs' own measured rule).

WHO WRITES IT OUT.  `UhdmWriter::writeInterface`
(src/DesignCompile/UhdmWriter.cpp:1626-1790):

    std::vector<Signal*> orig_nets = mod->getSignals();          // :1679
    writeNets(mod, orig_nets, m, dest_nets, s, signalBaseMap,
              netMap, portMap, instance);
    m->Nets(dest_nets);

`writeModule` does the same at :1457-1461 with the same `writeNets`.  ONE
producer, one writer, two holders.

THE TRILOGY'S FACT CONFIRMED IN THE SOURCE: `writeInterface` never calls

(:1572 and :1622), and `writeInterface`'s body contains none.  So the interface
DEFINITION's net list is settled entirely at COMPILE time, by the import copy.
