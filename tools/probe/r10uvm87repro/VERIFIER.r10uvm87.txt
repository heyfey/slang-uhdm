       pris    class_typespec (b87)     RIGHT

       Golden's class carries NO vpiTypedef entry for `rsp_t` at all — only
       `unsupported_typespec (rsp2_t)`.  The dependent typedef consumes the one
       it names.  `k6_87` (the consumed typedef belongs to the NON-winning
       parameter -> the surviving `rsp_t` still wins) and `k8_87` (`x_t`
       consumed, `y_t` survives -> golden `y_t`) read the same law from the
       other two sides, and `k7_87` (`typedef rsp_t rsp_q_t[$];` -> an
       `array_typespec`, `rsp_t` SURVIVES) fixes the consumer to a PLAIN named
       typedef with an EMPTY dimension list.  `k4_87` / `k5_87` (an unrelated
       class / `int` typedef) consume nothing.

   (b) AMONG ONE PARAMETER'S TYPEDEFS, THE FIRST WINS.  arms v87_a1 `c12_87`,

       re-read from the opposite side by v87_a1 `c11_87` (`typedef RSP rsp_t;`
       written BEFORE `typedef REQ req_t;` and golden still says `rsp_t`).

   (c) A QUALIFIED TYPEDEF IS NOT A CANDIDATE.          arm v87_a8 `v87`/`pv87`
       class v87 #(type REQ = e87, type RSP = REQ);

   THE FIX (src/TypeEmit.cpp, `classTpGroup87` only — 3 rules, ~30 lines, no
   new call site, no other law touched):
     * skip a TypeAlias whose syntax parent is a ClassPropertyDeclaration with a
       non-empty qualifier list;

       typedef of this body is written on;

       typedef of each parameter wins; the LAST PARAMETER still owns the group.
