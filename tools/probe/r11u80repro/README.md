## 2. THE DECODE (question 2)

### 2a. The producer's unpacked wrapper, and why the element is the scalar

`NetlistElaboration::elabSignal` decides net-or-variable ONCE, for the whole
signal, and the wrapper then wraps whatever it decided — the net side at
`NetlistElaboration.cpp:2534-2548`:

```

2535     array_net* array_net = s.MakeArray_net();
2536     array_net->Nets(s.MakeNetVec());
2537     array_net->Ranges(unpackedDimensions);

2539     array_net->VpiSize(unpackedSize);
...

```

and the variable side in `ElaborationStep::makeVar_` (:2171-2350), whose
`obj` was built by the `tpstype` switch at :1930-2023 — `uhdmenum_typespec ->
MakeEnum_var`, `uhdmstruct_typespec -> MakeStruct_var`, `uhdmunion_typespec ->
MakeUnion_var`, `uhdmint_typespec -> MakeInt_var`, and so on down the whole
class table. **The element's kind is the element typespec's own kind, and it
is the very object the SCALAR spelling of the same type would be** — there is
no second table.

`unpackedSize` is `CompileHelper::compileRanges`' out-parameter over the
WHOLE written dimension list (`NetlistElaboration.cpp:2193-2201`), so it is
the PRODUCT, not the outer width: `[0:1][0:2]` is 6 and `[0:1][0:2][0:3]`
is 24. It is NOT § fixedUnpackedCount6 — that law carries a param-sized quirk
(a `[N]` dim whose size is not an integer literal contributes 1) measured at
MODULE and CLASS scope, and `z1_arrgrid`'s `logic [7:0] z_szexp [2*2]` is the
arm that separates the two sites: golden's hoisted holder reads FOUR.

`vpiAutomatic` is written once, at `ElaborationStep.cpp:2408`, on the FINAL
object:

```
2408     if (sig->isStatic()) { obj->VpiAutomatic(false); }
2410     else                 { obj->VpiAutomatic(true);  }
```

and a package Signal is non-static exactly when the declaration matched
`data_declaration` rather than `net_declaration`
(`CompileHelper.cpp:2294`, `is_static = (component is ModuleDefinition ||
Program)` — FALSE for a package — against `compileNetDeclaration`'s
unconditional `sig->setStatic()` at :2186/:2200). That is
§ packageVarAutomaticIsDataDeclShape26's predicate, read on the hoisted
symbol: a bare type-identifier spelling is the NET one, a keyword-spelled
type or a `const`/`var` qualifier forces the DATA one.

The same `isStatic` term is ALSO the first clause of `elabSignal`'s
net-or-variable test (`NetlistElaboration.cpp:2074-2092`):

```
2074   bool isNet = true;
2075   if ((dtype && (subnettype == slNoType)) || sig->isConst() ||
2077       sig->isVar() || (!sig->isStatic()) ||
2079       (subnettype == slStringConst) || … Int|Integer|Byte|LongInt|
            Shortint|String|Real|RealTime|ShortReal|Event|Chandle|
            IntVec_TypeBit|Enum_base_type …
2090       || ((!sig->isVar()) && (subnettype == IntVec_TypeLogic))) {
2091     isNet = false; }
2101   if (netKeyword != slNoType) { isNet = true; }        // a NET KEYWORD wins
2133-2160  // THEN the TYPESPEC overrides: an all-logic/struct packed struct
           // flips it back TRUE; enum / bit / byte / real / class force FALSE.
           // A packed UNION is NOT on that list.
```

**`paIntVec_TypeReg` is absent from that list.** That single absence is the
whole of the difference between `w_t x[0:1]` (a `logic` typedef, `array_VAR`)
and `r_t x[0:1]` (a `reg` typedef, `array_NET`) — the SAME one-hop seam
§ caImportedPkgDefNetType77 already reads.

### 2b. The var qualifier's path through `getVpiNetType`

The def view stamps `dest_net->VpiNetType(getVpiNetType(orig_net->getType()))`
(`UhdmWriter.cpp:891`), and `Signal::getType()` is the node
`compileDataDeclaration` built the Signal from
(`CompileHelper.cpp:2396`, `sigType = fC->Type(intVec_TypeReg)` where
`intVec_TypeReg = Child(Child(variable_declaration))`). The `var` arm hops one
level FIRST:

```
2341    if (fC->Type(variable_declaration) == paVar_type) {
2342      variable_declaration = fC->Sibling(variable_declaration);
2343      var_type = true; }
2345    NodeId data_type      = fC->Child(variable_declaration);
2346    NodeId intVec_TypeReg = fC->Child(data_type);
```

so with `var` written, `Child(data_type)` lands PAST the base-keyword node and
the Signal carries `slNoType`, for which `getVpiNetType` answers 0. The
qualifier is not a semantic rule about nets; it is a one-node offset — and it
is golden, for every base keyword (arm `z2_varnt`, §3C).

## 4. THE TWO LAWS (question 4)

### LAW A — § caImportedPkgHoistUnpackedBuilder80 (`R11U80_HOLDER_OFF=1`)

`hoistKind77`'s unpacked branch and `makeHoistHolder77`'s two array arms, in
`src/ModuleEmit.cpp` (this pass's only production file). r11u77's reading is
kept VERBATIM behind the switch, so the law drops whole.

1. **net-or-variable** = `elabSignal`'s three steps: a `SymbolKind::Net` or a
   `reg` one-hop base keyword keeps NET, the DATA-declaration road
   (`pkgDataDeclRoad80`) forces VAR, and the ELEMENT typespec then overrides
   both (all-logic/struct packed struct -> NET; enum / 2-state integral /
   byte / real / class -> VAR).
2. **the element** is minted by `hoistElemClass80` from the element typespec's
   own class — the fourteen-row table the scalar road reads — and typed by the
   HOME PACKAGE'S OWN typespec object when the element is a typedef. An
   element class this builder does not mint returns `ArraySkip` and NO holder
   is written.
3. **`vpiAutomatic`** only on the DATA road (§ 26's predicate, `static`/
   `automatic` keywords honoured); **`vpiSigned`** by the shared
   § arrayVarSignedWritten8 predicate; **`vpiConstantVariable`** by the `const`
   modifier.
4. **`vpiSize`** = the product of the WRITTEN dimensions' widths — a size-style
   dim that NAMES a parameter contributing ONE
   (§ caImportedPkgHoistUnpackedSizeFolds80, CORRECTED by r11v80) — and one
   `vpiRange` per written dimension (`buildUnpackedRanges`, unchanged).
5. **the typedef'd-array spelling** gets golden's EMPTY holder — name,
   fullname, `vpiVisibility 1` and an `array_typespec`, and NOTHING else. The
   absence is transcribed, not filled. CORRECTED by r11v80
   (§ caImportedPkgHoistUnpackedTdRoad80): a `reg`-based array typedef takes
   the NET road, which carries NO `vpiVisibility`, and the UNQUALIFIED
   `array_typespec` name is golden only when the typedef's own written base is
   the `logic` keyword — a chain, a struct element, a nested array and the
   `reg` base all bind the home package's own QUALIFIED object.
6. **the element's NAME and net type** on the `array_net` side follow the
   ONE-HOP seam, not the element's class: `wire [7:0]` and a typedef CHAIN are
   unnamed and carry the holder's fullname, every one-hop named type is named
   and carries the doubled one and the written keyword.
