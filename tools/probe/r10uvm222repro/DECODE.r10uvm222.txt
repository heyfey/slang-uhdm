The gate is on WHERE THE CALLEE IS DECLARED (an interface's InstanceBody) — it
is NOT on how the call is WRITTEN.  A call an interface's own subroutine makes
to a sibling subroutine of the same interface, written BARE, reaches this arm
just as `vif.poke(x)` does; the only thing that then decides the object's KIND
is whether `find_last_of('.')` finds a dot ANYWHERE in the statement, arguments
included.  Nothing about this is specific to the corpus: it is reached in
EXPRESSION position too (grid cell c08 `return fn222(a_o.num222())`), at any
control depth (c09), from a second or last argument (c05/c06), and from a plain
dotted NAME that is not a call at all (c03).

5. THE FIX, KEYED ON THE CALLEE'S OWN FORM
-------------------------------------------
    std::string callee222 = raw1.substr(0, raw1.find('('));
    auto dot1 = callee222.find_last_of('.');

Cut the text at the argument list's opening paren FIRST, then take the last '.'
of what remains.  This is not a new idea in this file: the EXPRESSION-position
sibling arm ~100 lines above already reads the same text exactly this way
(`std::string calleeH = rawH.substr(0, rawH.find('('));`), and this pass makes
the two arms ask the same question of the same string.  ONE conjunct; no new
flag, no new counter, no new window.

WHERE THE TWO READINGS AGREE — everywhere the callee really is
receiver-qualified, because then the dot is before the paren.  Every arm cell
§ ifaceRecvCallArgTakesTheOrdinaryWindow176 decoded this arm on (s_plain,
s_local, s_formal, s_index, s_spaced) is byte-unchanged where its argument
carries no dot.

WHERE THEY COULD DISAGREE BESIDES THE TARGET — a receiver that is ITSELF A CALL
(`get_vif().poke(x)`), whose last dot also follows a '('.  Grid arm a6 writes
it: SURELOG COMPILES IT (rc 0) and SLANG REFUSES IT ("invalid member access for
type 'virtual interface if22f'", rc 3, no database).  The construct cannot
reach this emitter on any input, so the disagreement is unreachable.  THE RC IS
THE MEASUREMENT — a6 is recorded as an error-recovery arm, never as a golden
one.
An ESCAPED receiver identifier that CONTAINS a dot (`\u.esc .poke(...)`, arm
a5) keeps its pristine answer under both readings: the dot is still before the
paren.
