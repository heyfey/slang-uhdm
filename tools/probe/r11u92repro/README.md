## 2. THE DECODE (question 2)

### 2a. LAW A — the program road has no cell in it, from either direction

**(1) The written `assign` is compiled and thrown away.**
`CompileProgram.cpp:233-238`
(`~/git-repos/Surelog/src/DesignCompile/CompileProgram.cpp`):

```cpp
case VObjectType::paContinuous_assign: {
  if (collectType != CollectType::OTHER) break;
  m_helper.compileContinuousAssignment(m_program, fC, fC->Child(id),
                                       m_compileDesign, nullptr);
  break;
}
```

The returned vector is DISCARDED.  The module's arm for the same node
(`CompileModule.cpp:676-688`) keeps it:

```cpp
std::vector<UHDM::cont_assign*> assigns =
    m_helper.compileContinuousAssignment(m_module, fC, fC->Child(id),
                                         m_compileDesign, m_instance);
if (m_module->getContAssigns() == nullptr) { … }
for (auto assign : assigns) m_module->getContAssigns()->push_back(assign);
```

So `Program::getContAssigns()` is NULL however many `assign` statements the
program body carries.

**(2) The net-declaration assignment never reaches the program writer.**
Those cells are minted onto the INSTANCE's netlist by the signal walk
(`NetlistElaboration::elabSignal`, `NetlistElaboration.cpp:2708-2730`,
`netlist->cont_assigns()`).  `writeInstance` (`UhdmWriter.cpp:4146-4152`) and
the interface instance writer (`:4301-4307`) both drain that vector into the
object.  The program writers do not: `writeProgram` (`:1857`) and
`writeElabProgram` (`:2006`) each write

```cpp
m->Cont_assigns(mod->getContAssigns());
```

and nothing else.  The definition component's (null) vector is the ONLY thing
a `program` object can ever carry, in the DEFINITION view and the ELABORATED
view alike.  Two independent absences, one answer: no cell, ever.

### 2b. LAW B — the body declaration was the only thing making it a body net

This rides § `caNetDeclStrengthDropped90`'s decode.  That law's citation is an
ARM THAT IS NOT THERE: `CompileHelper::compileNetDeclaration`
(`CompileHelper.cpp:2131-2141`) walks the declaration's siblings itself and
has NO `paDrive_strength` / `paCharge_strength` arm, so
`wire (strong1, weak0) [31:0] o = 32'd12;` pushes NO `Signal` onto
`component->getSignals()`.

When the same name is ALSO a non-ANSI port, the net does not vanish — PORT
compilation minted it, which is why pass 89 guards the net face with
`isPortNet`.  But the body declaration the drop erased was the only thing
that made it a BODY signal, so what is left is exactly a
PORT-DECLARATION-ONLY net, and the producer treats it as one in every field
that reads the declaration: the listing GROUP (port group, after every body
declaration, in port-list order), the SPAN (the port-list name), the NET TYPE
(there is no keyword left to read: `getVpiNetType` is called on a Signal that
does not exist), the port's `Low_conn` form, and the port DEFAULT.
`n5_nonansi_noredecl` is the control that says what a port-declaration-only
net looks like, and our emitter already writes it correctly there
(`cmp rc=0` on both binaries) — so all five faces are "take the branch we
already have".

## 4. THE TWO LAWS, GATED (question 4)

### LAW A — § `caProgramHomeNoCells92`  (`ModuleEmit.cpp`, `emitContAssigns`)

One gate at the TOP of the function, BEFORE the first `Make` call, so nothing
is minted and discarded:

```cpp
if (m && m->UhdmType() == UHDM::uhdmprogram) {
    if (progTrace92()) fprintf(stderr, "R11U92PROG home=%s topView=%d drop=%d\n", …);
    if (!progCellsOff92()) return;
}
```

Its three callers are the module/program DEFINITION writer, the
module/program INSTANCE writer and the interface definition writer, so one
gate covers both program views and no other holder.  `instRefs` / `lhsSyms`
are collectors for objects this function builds; with no cells built there is
nothing to collect, and the caller's only use of `lhsSyms` (un-parenting a
typespec that a cell's Lhs elaboration re-pointed) has nothing to undo.

### LAW B — § `caStrPortNetRevertsToPort92`  (`EmitHelpers.h` + 4 sites)

`netDeclStrengthDrop92(sym)` is pass 89's predicate, re-stated where the
listing lives: walk the symbol's syntax up to its `NetDeclarationSyntax` and
answer `strength != nullptr` (slang's `NetStrengthSyntax` covers the drive and
the charge form alike); an IMPLICIT net has no declaration and answers no.
Five faces, five switches:

* **A (order)** and **B (anchor)** — in `collectNetOrder`, which now takes
  `strPortRevert` (default `false`, passed `true` by `emitModuleDef`'s and
  `emitInstance`'s net listings ONLY).  A reverted port lands in the
  `implicitPorts` group and its `bodyDecl` reads `false`, which is what every
  listing site already reads to choose the port-list name over the
  declaration.  The two are independent: with the anchor face off the item
  still moves group; with the order face off it still anchors at the port.
* **C (net type)** — `strPortRevertedNet92(it)` at the two net listings'
  `VpiNetType` stamp.
* **D (`Low_conn`)** — `emitPorts` already chooses between golden's two forms
  with `hasBodyDecl`; a reverted port is not `merged`.  MODULE/PROGRAM homes
  only (§3b).
* **E (input default)** — the elaborated input-port-default cell synthesizer
  reads the default from the PORT first and, failing that, from the internal
  symbol's declared type; the second source IS the erased declaration's
  initializer.  The guard is on that second source only, so a real ANSI port
  default (`input [3:0] delta = 10`) is untouched.

GOLDEN WRITES NOTHING ON A MISS: LAW A transcribes an absence, LAW B moves
objects we already emit and re-reads spans and forms golden already carries.
Neither law invents an object, a field or a binding.

## 8. THE INSTRUMENT FIX THIS PASS HAD TO MAKE

`cacell90.py::walk` promoted only `module_inst` / `interface_inst` /
`gen_scope` to holders, so a `cont_assign` inside a PROGRAM was attributed to
the enclosing MODULE's owner name and the program home could not be scored
per cell at all; `lister90v.py` matched `program_inst`, a kind the dumper
never prints.  `cacell92.py` is `cacell90.py` with `program` added to the
holder set (and its `main()` guarded so importers do not print a second
verdict); `lister92.py` and `netcell92.py` are built on that parser.  Without
the fix LAW A's own arms read `CELLS MATCH=2 OURS-ONLY=0` — a clean score on
a broken arm.
