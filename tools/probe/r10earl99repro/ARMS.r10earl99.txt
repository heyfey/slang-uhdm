g1_lit99 -- LITERAL x TARGET WIDTH (the arithmetic grid)
========================================================================
One 8-member struct {1, 4, 32, 64, 65, PW=12, 8, 8}; five cont_assigns, each a
ternary whose false arm is a fully-named pattern.  GOLDEN, measured:

  '1  -> vpiConstType 9 (UINT), vpiSize = THE MEMBER WIDTH, decompile = the
         DECIMAL of NumUtils::getMask(width)
            1 -> 1        4 -> 15        32 -> 4294967295
           64 -> 18446744073709551615
           65 -> 18446744073709551615   <-- getMask SATURATES AT 64 BITS and
                                            the flatten stores it whole, at
                                            vpiSize 65.  THE LANDMINE.
           12 -> 4095     8 -> 255
  '0  -> UINT 0 at the member width, decompile "0"      (all eight widths)
  'x  -> UINT 0 at the member width                     (all eight widths)
  'z  -> UINT 0 at the member width                     (all eight widths)
  1'b1 / 4'hF / 32'd7 / a package PARAMETER / a CONCAT -> UNTOUCHED, both
       sides, in every position: a SIZED or BASED literal is not
       `VpiSize() == -1` and the flatten never looks at it.

THE SIZE WALK, same arm, `om` row (mixed literals), golden first:
    [0] 1'b1            sz 1   both        [4] `'0` -> UINT 0   sz 65  both
    [1] 4'hF            sz 4   both        [5] q99::P4  sz 4 golden / 12 without
    [2] 32'd7           sz 32  both            the >=65 abort  <-- AWAY
    [3] `'1` -> UINT    sz 64  both        [6] {4'h3,4'h6} sz 0 golden / 8
                                           [7] `'x` -> UINT 0 sz 8 both
  Surelog stamps operands 0..4 and STOPS: its per-bit copy loop returns from
  the WHOLE expandPatternAssignment the first time the shift would reach 64
  (CompileHelper.cpp:5259-5265), and at i==0 the shift IS csize-1, so the
  65-bit member is the LAST one stamped.  Modelled; PATCHED reproduces golden
  operand for operand.

========================================================================

  REACHED by golden, NOT by this law (RANKED RESIDUES, unchanged by the pass):
    R1 a POSITIONAL pattern in a ternary arm (35:35/35:39) -- a DIFFERENT

       adjustOpSize -> adjustUnsized, whose rule is NOT the flatten's:
         golden `'1` -> UINT 7 sz 3 (re-typed) but `'0` -> BIN `'0` sz 5

         (CompileHelper.cpp:4921-4942) rewrites only when the value is 1.

       flattenPatternAssignments' OWN recursion
       (`opi = flattenPatternAssignments(s, fieldTypes[index], patt_op)`),
       which needs no carrier flag at all; our nested recursion passes
       `patFlatTs` but not the re-typing permission.
  NOT REACHED by golden either -- MUST STAY, and DID (byte-identical before
  and after):
    a plain ternary arm `sel ? 8'hff : '1`           (39)
    a REPLICATED pattern `'{2{'1}}`                  (38)
    an unbased literal as a CONDITION `('1 == sel)`  (41)
    an unbased literal in a CONCAT `{4'h0,{4{'1}}}`  (42)
    a pattern under an arm's ARITHMETIC (40:52) -- golden leaves it `'1` sz -1
    a PROCEDURAL assignment of a pattern (g4 n_proc)
  PRE-EXISTING, measured and NOT taken (identical before and after):
    R3 a FUNCTION ARGUMENT's `'1` (43:24): golden re-types it to
       BIN 11111111 sz 8 with a ref_typespec to the FORMAL's logic_typespec --
